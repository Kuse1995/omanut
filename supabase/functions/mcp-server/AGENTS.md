# mcp-server

- Company setup over MCP (`create_company`, `update_company`, `upload_media`, `create_product`, `update_product`) writes only an explicit field allowlist; billing, go-live, subscription, webhook, flow and Meta ids are never MCP-writable. New-company defaults live in `_shared/company-defaults.ts`, shared with the dashboard's `create-company` — never add a second defaults set. Pure validators live in `_shared/mcp-company-validators.ts` (tested).
- Publishing over MCP is gated: `publish_*` refuse with `blocked_by_test_mode` while `companies.test_mode` is true unless `force: true`, which is recorded in `scheduled_posts.metadata`. Facebook page resolution for publish, `dry_run`, `delete_published_post` and `get_connected_accounts` goes through the single `getPublishCredential` helper so they always agree on the destination.
- New tools throw `McpToolError` (`_shared/mcp-safety.ts`) for the `{ ok:false, error:{ code, message, field? }, next_step }` shape; the tool wrapper runs every error string through `redactSecrets`. Graph calls send the token in the Authorization header, never the URL. Destructive tools require an admin-scoped key and only act on records this system created.
